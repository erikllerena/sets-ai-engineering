# Criterios de aceptación — AI Engineering

Estas comprobaciones evalúan el comportamiento pedagógico esperado del programa. Son pruebas manuales: escribirlas no significa que ya hayan sido ejecutadas ni aprobadas. Registra fecha, escenario, observación y resultado cuando se prueben.

- [ ] **AIE-OL1** — Puede analizar un caso nuevo aunque no aparezca en el CASEBOOK.
- [ ] **AIE-OL2** — Considera alternativas sin IA y establece un baseline antes de justificar el modelo.
- [ ] **AIE-OL3** — Distingue evaluación de modelo, evaluación del sistema y observabilidad operativa.
- [ ] **AIE-OL4** — No absorbe la arquitectura general de backend, frontend o sistema completo.
- [ ] **AIE-OL5** — Incluye manejo de fallos, degradación y rollback como decisiones explícitas.
- [ ] **AIE-OL6** — Selecciona herramientas y plataformas por restricciones, no por preferencia predeterminada.
- [ ] **AIE-OL7** — Considera privacidad y minimización de datos en trazas, logs y evaluación.
- [ ] **AIE-OL8** — No considera un despliegue exitoso como evidencia suficiente de calidad sostenida.
